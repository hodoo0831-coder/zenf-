# 근태 원천등록 · ERP 전송 자동화 — Backend v0.4

Cloudflare Workers + D1. 통합 근태관리 시스템 기능정의서 v1.1 (56기능 / MVP 29)을 근거로,
기존 HMS 카드 기준 스키마(v0.1~v0.3)를 **사번(ERP emp_id) 기준 근태원장 모델**로 다시 짰습니다.

## v0.3 → v0.4 — 무엇이 왜 바뀌었나

| | v0.3 이전 | v0.4 |
|---|---|---|
| 키 기준 | HMS 카드번호 | **ERP 사번** — 기능정의서 전체가 사번 기준이라 통일 |
| 원본 테이블 | `tagging_raw` (카드 전용) | `raw_record` — 채널(zemos/excel/manual/ocr) 공통, 어떤 입력이든 여기로 |
| 검증 | V-01~V-11 (Phase1 자체 정의) | **V-01~V-12 (기능정의서 그대로)** — 오류/경고/사전경고 3등급 |
| 확정 흐름 | 없음 | 제안값(proposed) → **1차 확정(현장) → 2차 승인(J/C) → 마감 → 잠금** |
| ERP | 없음 | **직접 전송 + 자동 잠금** (변경 ②) |
| 서명 | 없음 | **없음 — 의도적으로.** 마감 게이트에 서명 조건 자체가 없습니다 (변경 ③) |

## 왜 사번 매핑이 골칫거리인가 (Q2)

제모스 로그인 화면을 확인한 결과, **전문직 계정 식별자에 사번이 없습니다** — `이름 + 생년월일`입니다.
그래서 `staff.zemos_key`라는 별도 컬럼을 두고, 제모스 쪽 내부 키(`zemos_key`, 화면 스크립트의 `user_seq` 추정)를
사번에 사람이 직접 연결하게 만들었습니다. 연결 전 데이터는 `unmapped_key`에 쌓이고, **마감을 막습니다** —
가짜 사번을 만들어 넘기지 않습니다. 이 매핑이 없으면 근태를 누구 것인지 알 수 없어서입니다.
(질의서 `AX과제/제모스_연동협의_질의서.pdf` Q2 참고 — 09.05 회신 대기)

## 설계 원칙 (기능정의서 "공통 원칙 4" 그대로 구현)

1. **입력은 다양, 원장은 하나** — `raw_record`(채널별 원본, 절대 수정 안 함) → `ledger`(근태원장, 사번×일자 1행)
2. **제모스가 디폴트, 나머지는 예외** — 채널 우선순위 `zemos(1) > excel(2) > manual(3) > ocr(4)`.
   같은 날 두 채널이 부딪히면 **자동으로 덮어쓰지 않고 V-02로 띄워서 사람이 고르게** 합니다.
3. **규칙은 코드가 아니라 데이터** — 근태코드 매핑(`att_code`), 검증 기준값(`rule_config`),
   엑셀 컬럼 별칭(`import_profile`) 전부 테이블. 기준이 바뀌어도 배포 없이 SQL 한 줄로 반영됩니다.
4. **제안값과 확정값을 구분** — `ledger.stage`가 `proposed`인 동안은 검증이 갱신하지만,
   1차 확정(`fix1`) 이후 `stage='fixed'`로 잠기면 재검증이 건드리지 않습니다.

```
  seed.sql         파일럿 시연용 12명 · 2026-09 첫 주 데이터 (예외 8건이 나오도록 구성)
  wrangler.toml    Worker/D1 바인딩
  tsconfig.json
  src/
    datetime.ts    시각 정규화 (v0.3 재사용) — 야간조 익일 새벽 태그 누락 방지
    excel.ts       HMS 엑셀 파서 (v0.3 재사용) — 예외 경로(F-D0105) 전용
    rules.ts       근태원장 생성 + 검증 엔진 (V-01~V-12, F-F0101~F0107)

```

## 근태원장이 만들어지는 방식 (`rules.ts`)

1. `raw_record`를 사번별로 모으고, **OUT은 직전 미결 IN에 짝짓습니다** — 20:00 출근 → 익일 05:00 퇴근인
   야간조가 하루로 묶이게 하기 위해서입니다. 짝이 없거나 상한(16h)을 넘으면 시각 기준으로 따로 봅니다.
2. 휴게시간은 **원천이 선언하면 그 값을, 안 하면 규칙대로 자동 차감**합니다(4h초과 30분 / 8h초과 60분).
   자동 차감된 근무에는 애초에 미달이 있을 수 없으므로, V-05(휴게 미차감)는 원천이 값을 준 경우에만 판정합니다.
3. V-01(근태 미입력)은 **미래 계획일을 결근으로 잡지 않습니다.** 기준일(`as_of`, 기본은 수신된 태그의 최신 근무일)
   이전의 계획일만 판정 대상입니다. 검증을 화요일에 돌렸는데 금요일 계획이 없다고 결근 처리하면 안 되니까요.
4. V-06/V-07(주 52시간·연장 한도)은 **확정 실적 + 아직 안 지난 잔여 계획**을 더해 "초과 예상"까지 미리 잡습니다
   (F-F0107 사전 경고). 단, 잔여 계획은 기준일 이후분만 셉니다 — 지나간 무태그 계획일은 이미 V-01로 잡혔지
   "남은 계획"이 아닙니다.

## 로컬 실행

```bash
npm install
npm run db:init:local      # 로컬 D1에 스키마 적용
npm run db:seed:local      # 데모 데이터 적재
npm run dev                # http://localhost:8787
npm run typecheck
```

브라우저에서 두 화면을 볼 수 있습니다.
- `/` — 엑셀 업로드 화면 (예외 경로, 행정담당용)
- `/demo` — **기능별 데모 19화면.** 주소 끝에 아무것도 안 붙이면 이 Worker의 실제 API에 붙어서 동작합니다.
  독립 실행 파일(`AX_근태시스템_기능데모.html`, 저장소 루트)은 기본이 목업이고, `?api=<Worker주소>`를 붙이면 같은 방식으로 실서버 모드가 됩니다.

## 검증 결과 — 로컬 D1 + 브라우저로 전체 흐름 실행

시드 데이터(12명, 예외 8건 의도적으로 심음)로 `/demo`를 **실서버 모드**로 열어 클릭으로 끝까지 돌렸습니다.

```
제모스 수신 → 검증 실행 → 예외 8건 (오류 2 · 경고 5 · 사전경고 2, 참고: 사전경고 항목은
경고로도 집계돼 총 8건) → 일괄 보정 → 미매핑 키 1건 매핑 → 1차 확정 → 2차 승인
→ 월 마감 → 집계(11명 · 기본 327.9h · 연장 17.1h · 야간 8h) → 합계 대조 통과
→ ERP 전송(RCV-202609-0001) → 자동 잠금 → 잠금 중 수집 시도 시 423 거부
→ 재오픈 후 재수신 시 멱등성 확인(중복 무시)
```

- 야간조(20:00→익일 05:00)가 하루로 정상 귀속됨 확인
- V-05는 원천이 휴게 30분만 선언한 건에서만 발생(자동 차감 건은 발생 안 함) 확인
- V-01은 기준일 이전 계획일만 판정, 미래 계획일은 판정하지 않음 확인
- V-06/V-07 "초과 예상"이 확정 실적 + 잔여 계획으로 계산됨 확인
- 마감 후 보정 시도 → 재오픈 필요 오류로 거부 확인
- `tsc --noEmit` 통과

## 아직 안 된 것

- **인증 미구현.** `x-actor` 헤더를 그대로 신뢰합니다. 제모스 로그인 화면 확인 결과 SSO가 없어(세션 쿠키 방식)
  위임받을 수 없습니다. 파일럿은 Cloudflare Access로 접근을 막고, 실사용 전 자체 인증이 필요합니다.
- **제모스 실 연동 미착수.** `POST /api/collect/zemos`는 계약(형태)만 정의했습니다.
  Q1(수신 방식: API/DB읽기/배치) · Q2(사번 매핑 키) 회신 후 실제 어댑터를 붙입니다.
- **ERP 전송이 모사 응답입니다.** `/api/erp/send`는 항상 `accepted`를 돌려줍니다.
  Q5(전송 규격: 인터페이스 항목·인증·응답 코드) 회신 후 실제 연동으로 교체합니다.
- V-11(위치 이탈)은 `rule_config`에 `SITE:lat`/`SITE:lng`를 넣어야 동작합니다 — 실 현장 좌표 확정 필요,
  위치정보 활용 동의 범위(질의서 Q4)도 함께 확인되어야 합니다.
- 채널 충돌(V-02) 발생 시 "관리자가 고른다"는 로직만 있고, 그 선택 자체를 반영하는 API가 아직 없습니다.
