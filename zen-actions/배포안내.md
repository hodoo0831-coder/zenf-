# ZEN 조치 공유 — 배포 안내

조치 티켓과 이력을 **사업장 단위로 공유**하는 Cloudflare Worker입니다.
배포하지 않아도 플랫폼은 그대로 동작합니다 — 다만 조치가 **그 브라우저에만** 남습니다.

## 왜 필요한가

지금까지 조치는 `localStorage` 에만 저장됐습니다. 그래서:

- 담당자를 `안전`으로 지정해도 **그 사람 화면에는 아무것도 뜨지 않았습니다**
- 다른 PC·다른 브라우저에서 열면 **보드가 비어 있었습니다**
- 조치 이력이 그 기기를 벗어나지 못해 **인수인계·감사에 쓸 수 없었습니다**

"담당·기한이 붙은 티켓"이라면 최소한 같은 사업장 안에서는 같은 보드를 봐야 합니다.

## 배포 (5분)

```bash
cd zen-actions

# 1) D1 생성 — 출력된 database_id 를 복사
wrangler d1 create zen-actions

# 2) wrangler.toml 의 database_id 를 붙여넣기

# 3) 스키마 적용
wrangler d1 execute zen-actions --remote --file=schema.sql

# 4) 배포
wrangler deploy
```

배포되면 `https://zen-actions.<계정>.workers.dev` 주소가 나옵니다.

## 플랫폼에 연결

**기준 · 연동 → ⑤ 조치 공유** 에 위 주소를 넣고 [연결].

연결되면 조치 보드 상단에 `조치 공유 — 공유 중 · N초 전 동기화` 가 뜹니다.

## 동작 방식

**로컬 우선(local-first)** 입니다. 플랫폼은 `localStorage` 로 그대로 돌아가고,
서버는 그 위에 얹는 동기화 계층입니다.

| 상황 | 동작 |
|---|---|
| 주소 미등록 | 지금까지와 동일 — 이 브라우저에만 저장 |
| 연결됨 | 조치를 건드릴 때마다 서버로 밀고, 60초마다 남의 변경을 받아옴 |
| **서버 끊김** | **조치는 계속 됩니다.** 로컬에 쌓아두고 배너에 `서버 미연결 — 로컬 저장 중` 표시 |
| 서버 복구 | 끊긴 동안의 변경이 자동으로 합쳐짐 |
| 같은 티켓을 두 사람이 수정 | 나중 수정본이 이김(`ts` 비교) |

이력(`actlog`)은 append-only 라 같은 회차가 두 번 올라와도 중복되지 않습니다.

## 엔드포인트

| 메서드 | 경로 | 설명 |
|---|---|---|
| GET | `/api/health` | 상태 확인 |
| GET | `/api/actions?site=` | 현재 티켓 + 최근 이력 (읽기 전용) |
| POST | `/api/sync` | `{site, by, actions, actlog}` → 병합 후 전체 상태 반환 |
| POST | `/api/reset` | `{site}` → 해당 사업장 전체 삭제 (초기화용) |

## 주의

- **접근 제어가 없습니다.** 주소를 아는 사람은 누구나 읽고 쓸 수 있습니다.
  사내에서만 쓰거나, 필요하면 Cloudflare Access 를 앞에 두세요.
- 사업장 구분은 `site` 문자열(`AP 대전공장`)입니다. 다른 사업장을 붙이려면
  플랫폼의 `ACT_SITE` 상수만 바꾸면 됩니다.
- 이력은 사업장당 최근 300건까지 돌려줍니다.
