# 포장재 창고 적치 관리 시스템 — 배포 안내

## 폴더에 들어있는 것

| 파일 | 용도 | 손댈 일 |
|---|---|---|
| `index.html` | 포털 — 현장/관리자 선택 (공유할 주소) | 없음 |
| `worker.html` | 현장 입력 앱 | 없음 |
| `admin.html` | 관리자 시스템 (암호 1996) | 없음 |
| `config.js` | **서버 주소 · 버전** | **여기 한 줄만 수정** |
| `icon.svg` / `icon-256.png` | 파비콘 · 홈 화면 아이콘 | 없음 |
| `netlify.toml` | 캐시·주소 설정 | 없음 |
| `wh-stack-worker.js` | Cloudflare Worker 코드 | 붙여넣기용 |
| `schema.sql` | D1 테이블 정의 | 붙여넣기용 |
| `wrangler.toml` | CLI 배포용 설정 | database_id 기입 |


현장(입력) · 관리자(확인) · 포털 3개 화면이 **Cloudflare Worker + D1** 한 곳을 바라봅니다.
정적 파일은 **Netlify**, 데이터는 **Cloudflare**가 맡습니다.

```
[현장 휴대폰] worker.html ┐
[관리자 PC]   admin.html  ├─→ wh-stack (Cloudflare Worker) ─→ D1 (wh-stack)
[포털]        index.html  ┘
```

---

## 1단계 — Cloudflare (데이터 서버)

### 대시보드로 하는 방법
1. Cloudflare → **Workers & Pages** → *Create* → *Worker* → 이름 `wh-stack` → Deploy
2. **Edit code** → 기존 내용 지우고 `wh-stack-worker.js` 전체 붙여넣기 → Deploy
3. **Storage & Databases** → **D1** → *Create* → 이름 `wh-stack`
4. `wh-stack` Worker → **Settings → Bindings → Add → D1 database**
   - Variable name: `DB`  (※ 반드시 대문자 DB)
   - Database: `wh-stack`
5. D1 `wh-stack` → **Console**에 `schema.sql` 내용 붙여넣고 실행
   (넣지 않아도 첫 요청 때 자동 생성되지만, 미리 넣어두면 확실합니다)
6. 브라우저에서 `https://wh-stack.<계정>.workers.dev/api/health` 열어
   `{"ok":true,...}` 가 보이면 완료

### CLI로 하는 방법
```bash
wrangler d1 create wh-stack          # 출력된 database_id 를 wrangler.toml 에 기입
wrangler d1 execute wh-stack --remote --file=schema.sql
wrangler deploy
```
`wrangler.toml`:
```toml
name = "wh-stack"
main = "wh-stack-worker.js"
compatibility_date = "2026-01-01"

[[d1_databases]]
binding = "DB"
database_name = "wh-stack"
database_id = "<생성된 id>"
```

## 2단계 — config.js 한 줄 수정

`config.js` 의 주소를 1단계에서 받은 Worker 주소로 바꿉니다.
이 파일 하나만 고치면 세 화면이 모두 같은 서버를 봅니다.

```js
window.ZEN_WH_API = "https://wh-stack.<계정>.workers.dev";
```

---

## 3단계 — Netlify (화면 배포)

1. netlify.com 로그인 → **Add new site → Deploy manually**
2. 이 폴더(`index.html`, `worker.html`, `admin.html`, `config.js`, `netlify.toml`)를
   통째로 드래그해서 올립니다
3. 배포되면 주소가 나옵니다 → **Site configuration → Change site name** 으로
   `zen-wh-stack` 같이 알아보기 쉽게 변경
4. 접속 경로
   - 포털 `https://<사이트>.netlify.app/`
   - 현장 `https://<사이트>.netlify.app/worker.html`
   - 관리자 `https://<사이트>.netlify.app/admin.html`

> 파일을 고쳐 다시 올릴 때는 같은 화면에 다시 드래그하면 덮어써집니다.
> `netlify.toml` 이 HTML·config.js 캐시를 끄도록 잡아둬서, 새로 고치면 바로 반영됩니다.

---

## 4단계 — 현장 배포

1. 현장 관리자 휴대폰에서 포털 주소 접속 → **현장 입력** → 홈 화면에 추가
   (아이폰: 공유 → 홈 화면에 추가 / 안드로이드: ⋮ → 홈 화면에 추가)
2. 앱에서 **설정 → 이름**만 입력하면 끝. 서버 주소는 config.js 값이 자동으로 들어갑니다
3. 관리자 화면은 접속하면 헤더에 `실시간 연결중` 이 뜨고, 30초마다 제출 현황이 갱신됩니다

## 확인 순서 (연동 점검)

| 순서 | 하는 일 | 정상 결과 |
|---|---|---|
| 1 | `/api/health` 접속 | `{"ok":true}` |
| 2 | 현장앱에서 아무 구역 제출 | "제출 완료 · n PLT" 토스트 |
| 3 | 관리자 화면 열기 | 헤더 `실시간 연결중`, 제출 현황에 해당 구역 표시 |
| 4 | 관리자에서 **확인** 클릭 | 현장앱 그 구역이 `확인완료`로 잠김 |
| 5 | 관리자에서 **이 수치를 적재수로 반영** | 배치도·추이·재배치 제안이 그 날짜로 갱신 |
| 6 | 포털 새로고침 | 오늘 적치율과 구역별 막대 표시 |

## 관리자 암호

- 초기 암호 **1996** (관리자 화면 진입 시 스플래시에서 입력)
- 한 번 들어가면 그 탭이 닫힐 때까지 다시 묻지 않습니다. 헤더의 🔒 버튼으로 즉시 잠글 수 있습니다
- 암호 변경은 관리자 화면 하단 **암호 변경** 링크 (변경 후에는 그 브라우저에만 적용)
- 이 잠금은 **화면 가리기 수준**입니다. 브라우저에 저장되는 방식이라 기술적으로 우회가 가능하니,
  외부 유출이 곤란한 데이터라면 Cloudflare Access로 관리자 주소에 사내 계정 인증을 거는 편이 안전합니다

## 데이터 구조

- `stock` — 날짜 · 구역 · 로케이션별 파렛트 수 (재제출 시 해당 구역만 덮어씀)
- `submits` — 날짜 · 구역별 제출자 · 제출시각 · 상태(submitted / confirmed)

관리자가 **확인**한 구역은 현장에서 재제출이 막힙니다(409). 수정이 필요하면
관리자가 **확인 취소**를 눌러 다시 열어주면 됩니다.
