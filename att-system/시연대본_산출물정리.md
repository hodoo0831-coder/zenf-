# 2. 실제 구현물 현황 (att-system)

md의 기능을 실제로 동작하는 코드로 옮긴 것. Cloudflare Workers + D1.

```
backend/     API 서버 (스키마 20+테이블, 엔드포인트 40+)
frontend/index.html    관리자·J/C·시스템관리자 콘솔
frontend/worker.html   근로자 모바일 웹
```

## 2-1. 동작이 확인된 것 (로컬에서 실제로 실행·클릭 검증)

| 영역 | 상태 | 확인 방법 |
| --- | :-: | --- |
| 검증엔진 V-01~V-15 | ✅ | 30명·31일 시드로 실행. V-13(지각)·V-14(미승인연장) 실제 케이스 주입해 발동 확인 |
| 근태원장 4단 구조 | ✅ | 원본 불변 · 보정 시 이력 append · 사유 없으면 저장 차단 |
| 예외 오류/경고 구분 | ✅ | 오류는 사유만으로 통과 불가(API에서 차단), 실제 보정해야만 해소되는 것 확인 |
| 재검증 시 예외 누적 방지 | ✅ | `last_run_id`로 최신 실행만 노출 (버그 잡아서 수정함) |
| 현장×월 확정 단위 | ✅ | 1차확정 → 2차승인 → 마감 → 스냅샷 봉인(해시) 전 과정 실행 |
| 1차확정 체크리스트 4조건 | ✅ | 대기 중 연장신청 1건 때문에 확정이 막히는 것 확인 |
| 정정요청 워크플로 | ✅ | 근로자 제출 → 관리자 승인 → 확정값 반영 → 재검증 시 해당 예외 소멸까지 |
| 연장근로 신청 | ✅ | 사후 신청 사유 10자 미만 거부 확인 |
| 근무계획 + 52h 시뮬레이션 | ✅ | 마감월 잠금·과거소급 사유 강제 확인 |
| 내보내기 양식 엔진 | ✅ | 5종 양식, 현장고유표기 역매핑(`○`), 고객사용 비식별 강제(익명 처리), 사유 없으면 차단, 합계 대조, CSV 다운로드 |
| 근로자 모바일 5화면 | ✅ | 390px 화면에서 제출까지 동작 |

## 2-2. 아직 안 되는 것 — **여기가 중요하다**

| 항목 | 상태 | 왜 |
| --- | :-: | --- |
| **제모스 실연동** | ⛔ Mock | A/B/C 방식 미확정(§12 ★). 지금은 항상 0건 반환. 그동안은 엑셀·수기 채널로만 원장이 채워진다 |
| **ERP DB 직접 INSERT** | ⛔ 어댑터만 | **코드 문제가 아니라 인프라 문제.** Cloudflare Workers가 사내 ERP DB에 네트워크로 닿을 수 있는지부터 정해야 함. 현재는 FILE 폴백만 동작 |
| **로그인** | ⚠️ 임시 | `X-User-Id` 헤더로 사용자 식별. SSO 방식 미정(§12) |
| **OCR 인식** | ⚠️ 큐만 | 이미지 참조를 검토대기로 쌓고 **사람이 값을 직접 입력**해 확정하는 구조. 실제 인식 엔진 없음 |
| 고객사 리포트 전용 화면 | ⛔ | 내보내기 화면에서 FMT-04 선택으로 대체 가능하나 전용 UI 없음 |
| J/C 통합 대시보드 · 제모스 수신현황 화면 | ⛔ | API는 있고 화면만 없음 |
| Cloudflare 실제 배포 | ⛔ | 계정 접근 권한이 있는 환경에서 `wrangler deploy` 필요 |

# 3. 09-04 오전에 내가 잘못 판단했던 것 (정정)

> "근로자 서명 기능 제외"를 **"근로자 접근 자체를 제외"** 로 과하게 해석해서, 백엔드에서 근로자 role을 통째로 뺐었다.

**정정** — 기준 문서 §11-①에 따르면 근로자는 **서명만 없고, 조회 + 정정 요청 + 연장근로 신청은 그대로 있다.** 이 부분은 이후 재설계에서 바로잡아 근로자 role·모바일 웹·정정요청·연장신청을 모두 복원했다.

`기능정의서_v1.2.xlsx`의 F-A0103(로그인) 항목에 이 잘못된 해석이 반영돼 있으므로, **그 파일의 해당 항목은 신뢰하지 말 것.**

# 4. 월요일 시연 대본

## 4-1. 무엇으로 시연하나

두 가지 중 선택한다.

| 옵션 | 대상 | 장점 | 단점 |
| --- | --- | --- | --- |
| **A. `attendance_system.html`** | TF 보고 · 임원 | 화면이 완성돼 있고 3개 현장·23명 시나리오가 이미 들어있음. 브라우저만 있으면 됨 | 실제 서버가 아님 |
| **B. att-system (백엔드+콘솔)** | 개발 착수 협의 | 진짜 API·DB가 도는 것을 보여줌 | 화면이 기능 위주라 투박함 |

> **권장** — TF 보고는 A, 이민아·박주노 대리님과의 개발 협의는 B. 둘은 경쟁 관계가 아니라 **A가 목표 화면, B가 그 목표를 실제로 구현한 뼈대**다.

## 4-2. 옵션 A 시연 동선 (기준 문서 §14-2 그대로)

`m01` → `j01` → `w01` → `a01` 순서로 15단계. 문서 §14-2 표 참조.
**주의** — 10번(ERP 전송) 전에 8번(마감)을 먼저 실행해야 전송 버튼이 활성화된다.

## 4-3. 옵션 B 시연 동선 (개발 협의용, 약 10분)

사전 준비:
```bash
cd backend && npm install
npx wrangler d1 execute att_db --local --file=./schema.sql
npx wrangler d1 execute att_db --local --file=./seed.sql
npx wrangler dev --local --port 8787
```
그 다음 `frontend/index.html`을 열고 API 주소를 `http://localhost:8787`로.

| # | 화면 | 보여줄 것 | 말할 것 |
| :-: | --- | --- | --- |
| 1 | 예외 처리 → 검증 실행 | 588건 검사 → V-01 대량 발생 | "제모스가 Mock이라 계획일 태그가 다 비어있다. **결근으로 자동 처리하지 않고** 전부 '확인 필요'로 올린다 — 이게 설계 원칙" |
| 2 | 예외 목록에서 오류 1건 클릭 | 사유 입력창이 아니라 **실제 근태 입력 폼**이 뜸 | "오류는 사유만 써서 넘길 수 없다. API 레벨에서 막아뒀다" |
| 3 | 보정 저장 → 검증 재실행 | 587로 정확히 1건 감소 | "재실행해도 이전 예외가 누적되지 않는다" |
| 4 | 근로자 모바일(worker.html, W-01) → 수정요청 제출 | 승인대기 생성 | "근로자는 서명은 안 하지만 조회·정정요청은 한다" |
| 5 | 콘솔 → 정정·연장 검토 → 승인 | 확정값 자동 반영 | "승인이 곧 F-G0203 확정값 보정으로 이어진다. 원본은 그대로" |
| 6 | 확정·마감 → 1차확정 시도 | 체크리스트 4조건 중 미충족으로 차단 | "현장×월 단위 확정. 근로자 개별 승인 없음" |
| 7 | 내보내기 → FMT-01 생성 | `○ 08:00~17:00` 형태 CSV | "같은 데이터가 양식에 따라 다르게 나온다. 현장이 늘어도 개발 불필요" |
| 8 | 내보내기 → FMT-04 생성 | 사번이 `익명-1`로 | "고객사 제출은 비식별이 강제로 켜지고 끌 수 없다" |
| 9 | 사유 비우고 생성 시도 | 차단 | "다운로드 사유는 필수, 이력은 삭제 불가" |
| 10 | ERP 전송 | "API 미개방" 정직한 응답 | "**여기가 지금 막혀 있다.** §12 미결 ★ 4건이 안 풀리면 F0와 F3이 못 움직인다" |

## 4-4. 시연에서 반드시 말해야 할 것

1. **제모스·ERP가 Mock이다** — 숨기지 말 것. 이게 안 풀리면 전체가 멈춘다는 게 오히려 핵심 메시지다.
2. **ERP DB 직접 전송은 코드가 아니라 인프라 문제** — "만들면 되는 것"이 아니라 접근 권한·네트워크 결정이 먼저다.
3. **오류는 사유로 못 넘긴다** — 노무 리스크 대응의 핵심 장치.
4. **근로자 서명은 없지만 근로자 접근은 있다** — 조회 이력·정정요청 이력·4단 이력 3가지가 서명을 대체하는 통제다.
