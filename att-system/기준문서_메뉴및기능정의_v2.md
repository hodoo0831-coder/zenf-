# 0. 시스템 개요

## 0-1. 한 줄 정의

> **제모스가 찍고 → 이 시스템이 검증·확정하고 → ERP DB로 바로 쏜다.**

근태 원천은 근로자가 이미 쓰고 있는 **제모스**다. 이 시스템은 그 기록을 받아 검증·예외처리·확정·마감하고, 확정된 집계를 **ERP 근태 테이블에 직접 적재**한다.

## 0-2. 시스템 경계 — 무엇을 만들고, 무엇을 안 만드는가

| 구분 | 처리 방식 | 본 시스템 |
| --- | --- | --- |
| 계정 · 로그인 인증 | 외부 솔루션 계정 데이터 이용 | ❌ 계정·비밀번호 관리 없음 · ⭕ 인증 결과 수신 후 역할·범위 판정만 |
| 사원 마스터 (인사정보) | ERP 인사에서 수신 (읽기 전용) | ❌ 인사정보 등록·수정 없음 |
| **출퇴근 태그** | **제모스에서 발생 → 데이터 수신** | ❌ 출퇴근을 찍는 화면 없음 |
| 연차 · 휴가 신청 | 기존 그룹웨어 / 제모스에서 처리 | ❌ 휴가 신청 없음 (조회·대조만) |
| **근로자 서명** | **도입하지 않음** (§11 결정 ①) | ❌ 서명 화면 없음 · 근로자는 조회 + 정정 요청까지 |
| 근태 등록·검증·승인·마감 | 본 시스템 | ⭕ **핵심 범위** |
| 근태 집계 | 본 시스템 | ⭕ |
| **ERP 근태 등록** | **시스템이 ERP DB에 직접 INSERT** | ⭕ 파일 생성 없음 · 사람의 수동 업로드 없음 |
| 현장별 엑셀 산출물 | 본 시스템 (양식 정의 기반) | ⭕ |

## 0-3. 제모스에 대한 전제

1. **제모스는 수정하지 않는다.** 이미 운영 중인 근로자 앱이며, 이번 과제에서 앱 자체를 건드리지 않는다.
2. **그래서 사이트를 별도로 만든다.** 검증·마감·ERP 전송·관리자 업무는 신규 웹에서 수행한다.
3. **근로자에게 새 앱을 설치시키지 않는다.** 출퇴근은 제모스에서, 확인·정정 요청은 문자로 받은 링크의 모바일 웹에서.
4. **제모스에 쓰기(write)를 하지 않는다.** 읽기 전용 수신만.
5. **최종 목표는 제모스 이식.** 파일럿 검증 후 신규 시스템의 기능을 제모스로 옮겨 전 그룹사 공통으로 쓴다.

> **이식을 전제로 한 설계 원칙** — 근태 판정 · 코드 변환 · 한도 계산 · ERP 전송 · 양식 생성은 **화면에 붙이지 않고 서버 로직(API)으로 분리**한다. 제모스가 화면만 바꿔 달아도 로직을 재개발하지 않아도 되게 한다.

# 1. 역할 · 권한

## 1-1. 역할 4개

| 역할 | 사용 환경 | 데이터 범위 | 주요 행위 |
| --- | --- | --- | --- |
| **근로자** | 제모스 앱 + 모바일 웹(문자 링크) | 본인 · **확정 대상월 1개월** | 내 근태 확인 · 정정 요청 · 연장근로 신청 |
| **현장관리자** | PC 웹 (모바일 병행) | 담당 현장 1개의 근로자 전체 | 예외 건 수정 · 특이사항 기재 · **현장 1차 확정** · 엑셀 내보내기 |
| **J/C** | PC 웹 | 배정된 고객사 · 현장 전체 | **현장 2차 승인** · 반송 · **월 마감** · 집계 · **ERP 전송** · 고객사 자료 |
| **시스템관리자** | PC 웹 | 기준정보 · 권한 · Rule (근태 원본 조회 제한) | 기준정보 · 검증 Rule · 매핑 · 내보내기 양식 · 연동 · 권한 |

> 엑셀 기능정의서의 `본사 인사·급여`, `고객사 담당자` 역할은 **J/C로 통합**됐다. 고객사는 별도 로그인 없이 J/C가 생성한 비식별 리포트를 수령한다.

## 1-2. 권한 표기

`◎` 주 수행(등록·수정·실행) · `◆` 승인·결재 · `○` 조회만 · `▲` 신청·요청만 · `△` 제한적(본인/담당현장) · `−` 권한없음

# 2. 처리 단위 — 이 시스템의 핵심 개념

**단위를 섞으면 안 된다.** 근태 데이터는 근로자 단위로 다루지만, **확정·승인·마감·전송은 현장 단위**다.

| 단계 | 단위 | 근거 기능 |
| --- | --- | --- |
| 수집 · 표준화 · 검증 · 예외처리 · 확정값 보정 | **근로자 × 일자** | F-D01xx · F-E01xx · F-F01xx · F-G0203 |
| **1차 확정 · 2차 승인 · 반송 · 마감 · 잠금 · ERP 전송** | **현장 × 월** | F-G0204 · F-G0302/0303 · F-H0101/0102 · F-I0102 |
| 집계 | 근로자 × 월 (마감된 현장만) | F-I0101 |

**의미**

- 근로자 한 명씩 승인하지 않는다. 현장의 근태가 조건을 충족하면 **`현장 × 월` 전체를 1건으로** 확정하고, J/C도 같은 단위로 승인한다.
- 확정 상태는 근태원장이 아니라 **현장 상태 레코드**가 들고 있다.

```
현장상태[현장ID | 월] = {
  mgrOk, mgrBy, mgrAt, mgrOpin      // 현장 1차 확정
  jcOk,  jcBy,  jcAt,  jcOpin       // J/C 2차 승인
  closed, closedAt, locked          // 월 마감 · 잠금
  returned                          // 반송 누적 횟수
  erpVer                            // ERP 전송 버전
}
```

- 마감 잠금 판정(쓰기 차단)도 **소속 현장의 마감 상태**를 본다.

# 3. 데이터 상태 전이

```
[수집]         [표준화]        [검증]         [1차]        [2차]       [마감]
제모스 ────→ RAW 적재 ──→ 코드매핑 ──→ 규칙실행 ──→ 현장확정 ──→ 현장승인 ──→ 현장마감·잠금
직접입력/엑셀   (불변)      정합성처리    V-01~V-15     F-G0204     F-G0302     F-H0101/0102
OCR/데이사인   F-E0101    F-E0102/3   자동승인 F-F0106            F-G0304          │
                                                                                ▼
                                                          집계 F-I0101 ──→ ERP DB 직접 전송 F-I0102
                                                                          ─→ 현장 엑셀 산출 F-I0110
```

## 3-1. 제안값과 확정값

| 구분 | 무엇 | 쓰임 |
| --- | --- | --- |
| **제안값** | 제모스 수신값 · 근로자 입력값 · OCR 인식값 | 화면 표시 · 검토 대상 |
| **확정값** | 현장관리자가 확정한 값 | **ERP 전송과 급여는 확정값만 사용** |

## 3-2. 4단 이력 구조

`원본 → 정정 요청 → 관리자 승인값 → 최종 확정값` — 각 단계의 주체 · 일시 · 사유가 필수다. **원본은 어떤 단계에서도 수정되지 않는다.**

## 4-5. 제모스 연동 (F0)

| 항목 | 값 |
| --- | --- |
| 수신 경로 | **방안 C — 일 배치 파일** (A 조회API / B DB읽기전용 / C 배치파일 중 택1, §12 미결) |
| 수신 주기 | 매일 08:00 |
| 수신 대상 | ① 출근·퇴근 태그(일시·GPS/비콘·현장) ② 연차·반차 신청 ③ 근로자–현장 배치 |
| 제모스 쓰기 | **없음 (읽기 전용)** |

**수신 처리 규칙 6가지**

1. **수신 즉시 원장에 `제안값`으로 적재** — 채널 = 제모스, 원본 payload 보관
2. **위치 검증** — 태그 위치가 배정 현장 반경(300m) 밖이면 상태 `확인 필요` (V-11)
3. **근무시간 산출** — 출·퇴근 태그 쌍으로 계산, 휴게는 현장 규칙에 따라 차감
4. **중복 태그** — 동일 일자 다중 태그는 **최초 출근 · 최종 퇴근**으로 집계하고 원본은 전건 보관
5. **재수신(정정)** — 값이 바뀌어 다시 들어오면 새 버전으로 적재. 단 **이미 마감된 기간은 반영하지 않고 차월 소급 대상으로 표시**
6. **수신 실패 감시** — 예상 건수 대비 수신 0건 또는 연동 오류 시 알림 + 엑셀 업로드 대체 경로 안내

# 6. 화면별 기능 정의

## 6-1. 근로자

### `w-home` 내 대시보드 (SCR-W-01) ★

| 영역 | 내용 | 근거 |
| --- | --- | --- |
| 이번 달 요약 | 실근로시간 · 연장 · 야간·휴일 · 연차 사용 · 확인 필요 건수 | F-G0101 |
| **주 52시간 게이지** | 최다 근로 주 기준 누적/한도 · **잔여 가능 시간** · 초과 예상 표시 | F-F0107 |
| 내 신청 진행 상태 | 수정요청 · 연장근로 승인 상태 | F-G0102 / F-G0103 |
| 확인이 필요한 근태 | 본인 관련 예외만 (일자·근태·출퇴근·사유·조치) | F-F0105 △ |
| 이번 달 근무 일정 | 예정 근무일 · 예정 출퇴근 시각 | F-C0104 |

**처리규칙** — 본인 데이터만 / 미수집 일자는 `기록 없음` 명시(임의 추정 금지) / 게이지는 `당일까지 누적 + 잔여 계획` 기준의 **초과 예상**값

### `w-sch` 내 근무일정 (SCR-W-02)

월 캘린더 뷰. 확정된 근무계획을 표시하고, 미등록 기간은 `계획 없음`으로 명시한다. (F-C0104)

### `w-att` 내 근태 확인 (SCR-W-03)

일별 **예정(계획) vs 실적(수집)** 대조표. 필터: 전체 / 근무일 / 확인 필요 / 보정 이력.

**처리규칙**
- **원본과 확정값 차이가 있으면 양쪽 모두 표시** (예: 원본 09:24 / 확정 09:00)
- 수집채널을 함께 표시해 출처를 추적할 수 있게 한다
- 미수집 일자는 `기록 없음`
- 하단에 **변환·변경 이력 추적** (원본 → 매핑 → 정합성 → 검증 → 정정요청 → 확정값 보정) — 조회 행위도 Audit Log에 기록 (F-E0105 / F-J0105)

### `w-req` 근태 수정요청 (SCR-W-04)

| 항목 | 내용 |
| --- | --- |
| 입력 | 대상 일자 · 요청 항목(출근/퇴근/근태구분/휴게) · 요청 값 · **사유(필수)** · 증빙 파일 |
| 출력 | 수정요청 건 생성(상태 `승인대기`) + 현장관리자 알림 |
| 처리규칙 | **원본 변경 없이 요청 건만 생성** / 사유 미입력 시 저장 차단 / **마감된 월은 요청 불가** |
| 후행 | `m-exc` 현장관리자 검토 → F-G0203 확정값 보정 |

예외로 분류됐지만 아직 요청하지 않은 날짜를 상단에 **요청 후보**로 제시한다.

### `w-ot` 연장근로 신청 (SCR-W-05) ★

| 영역 | 내용 |
| --- | --- |
| 상단 | 주 누적 근로시간 / 52h 게이지 / **잔여 가능 연장시간** |
| 신청 폼 | 일자 · **사전/사후 토글** · 시작~종료 시각 · 연장시간 자동계산 · 업무 사유 |
| 경고 배너 | 한도 초과 예상 시 `이 신청을 포함하면 주 XX시간 (한도 초과)` — 실시간 재계산 |
| 사후 승인 후보 | 연장이 발생했으나 승인 건이 없어 E06으로 분류된 날 목록 |
| 하단 | 내 신청 이력 (일자·시간·사전/사후·상태·가산 반영) |

**처리규칙**
1. **미승인 연장은 예외(E06)로 유지** — 승인 없이는 가산 대상에서 제외
2. 주52시간 초과 예상 시 **신청 단계에서 경고** + 잔여 가능 시간 제시
3. **사후 신청은 상세 사유 필수**(10자 이상)
4. 마감된 월은 신청 불가

**공통 처리규칙 (v2 공통원칙 4가지)**

1. **입력은 다양, 원장은 하나** — 어떤 채널이든 저장은 단일 근태원장. 원장에 채널·원본 payload를 보관해 출처를 추적
2. **제모스가 디폴트, 나머지는 예외** — 같은 사번·일자에 제모스 기록과 다른 채널 기록이 동시에 있으면 **제모스를 원천, 다른 채널을 보정값**으로 본다. **자동으로 덮어쓰지 않고** 양쪽을 나란히 보여주고 관리자가 선택 (V-15)
3. **규칙은 코드가 아니라 데이터** — 코드 매핑 · 결근 판정 · 한도 · 허용오차 · 현장 반경은 현장별 규칙 레코드
4. **제안값과 확정값을 구분** — ERP 전송과 급여는 확정값만 사용

**자동 판정** — 근무계획 × 제모스 태그가 허용오차(±10분) 내로 일치하면 상태 `정상`, 기본 접힘. **어긋난 사람만** `확인 필요`로 올린다.

**출력** — Excel 내보내기 (양식 선택 → 표시 옵션 → 사유 입력 → 다운로드) — §9 참조

# 8. ERP 근태 전송 (F-I0102)

## 8-1. 방식 — 파일 없이 DB에 직접 적재

확정 집계를 시스템이 **ERP 근태 테이블에 직접 INSERT**한다. 파일(xlsx)을 만들지 않고, **사람이 ERP 화면에서 업로드하는 단계도 없다.**

| 대상 테이블 | 내용 |
| --- | --- |
| `ERP_HR.TB_MON_ATT` | 월근태 — 사번 · 일자 · ERP 근태코드 · 실근로시간 |
| `ERP_HR.TB_OT_ATT` | 시간외근무 — 연장 · 야간 · 휴일 시간 및 가산 대상 시간 |

## 8-2. 처리 규칙

1. **전송 단위** — 현장 × 월. **마감 완료 현장만** 전송 가능, 미마감은 차단
2. **트랜잭션 단위** — 한 현장·한 기간의 월근태와 시간외근무를 **하나의 트랜잭션**으로 INSERT. 일부라도 실패하면 **전건 롤백**. 부분 반영 금지
3. **멱등 재전송** — 동일 기간·현장 재전송 시 **기존 행 삭제 후 재적재**하고 버전 증가. 중복 적재 없음
4. **전송 후 자동 대조** — 전송 직후 ERP를 **역조회**해 총 인원 · 총 공수 · 총 연장시간 대조. 불일치 시 실패 처리 + 롤백
5. **마감 스냅샷 불변** — 마감 후 발견된 오류는 스냅샷을 수정하지 않고 **차월 소급분**으로 처리
6. **집계 검증 선행** — 합계 대조(F-I0106) 불일치 시 전송 차단
7. **코드 변환** — 내부코드 → ERP 코드(§4-2). 미정의 코드는 V-10에서 마감 단계에 선차단되므로 전송 시점에는 존재하지 않음

## 8-3. 화면

| 탭 | 내용 |
| --- | --- |
| 전송 실행 | 현장별 대상(인원·마감 여부·월근태 행수·시간외 행수·전송 상태·버전) · **행별 전송 버튼** · 전송 방식 · 코드 변환표 · F3 완료 기준 |
| 전송 이력 | 전송 일시 · 수행자 · 버전 · 적재 행수 · **역조회 대조 결과** · 결과 · 오류·롤백 · **실패 건 원본 근태 역추적** |

**버튼 위치**
- 화면 상단 우측 **`📤 ERP 전송 실행 (N개 현장)`** — 마감 완료 현장 일괄 전송. 대상이 없으면 비활성 + 사유 툴팁
- 표 `전송` 열 — 미마감이어도 **비활성 버튼으로 노출**(툴팁 안내). 전송 완료 현장은 `🔄 재전송`
- 사이드바 메뉴 **배지** — 마감됐으나 미전송인 현장 수
- `월 근태 마감` · `근태 집계·검증` 화면에서 `ERP 전송 →` 동선 제공

## 8-4. 완료 기준

1. **ERP 전송 실패 0건** — 실패 건은 전건 롤백 + 원본 근태 역추적
2. **기간 선택 → 전송 완료 5분 이내** — 파일 작성·업로드 단계 없음
3. **ERP 총 공수 = 확정 근태 합계** — 역조회 대조 100% 일치, 불일치 시 롤백

# 9. 내보내기 양식 (F-I0110)

## 9-1. 개념 — 매핑의 역방향

| 방향 | 기능 |
| --- | --- |
| 입력 | 현장별 표기 → 표준코드 (`F-J0102`) |
| **출력** | **표준 원장 → 현장별 양식** (`F-I0110`) |

근태원장은 항상 `1건 = 사번 × 일자` 롱 포맷으로 저장된다. 현장이 원하는 피벗은 그걸 돌려놓은 것이므로, 양식을 **파라미터 조합으로 표현**하고 **현장별 레코드로 저장**한다. 현장이 늘어나도 개발이 필요하지 않다.

| 파라미터 | 값 |
| --- | --- |
| 행 축 | 사번 / 성명 / 직군 / 현장 (복수) |
| 열 축 | 일자 1~말일 / 주차 |
| 셀 값 | 근태코드만 / 출·퇴근시각 / 실근로시간 / 근태코드 + 시각 |
| 코드 표기 | 내부코드(100) / 코드명(정상근무) / **현장 고유표기(○, 평일)** |
| 합계열 | 근무일수 · 실근로 · 연장 · 야간 · 휴일 · 연차 · 결근 (복수) |
| 용도 | 현장 제출 / 고객사 제출 / 내부 관리 |
| 비식별 | 원본 / 비식별 (고객사 제출 시 **강제 ON**) |

## 9-2. 대표 표기 선정 규칙 (역매핑 다대일 해소)

1. 해당 **고객사 전용 표기**가 있으면 그것을 쓴다 → 대한물류 `평일`, 한빛커머스 `○`
2. 없으면 **전체 공용 표기** → `정상`
3. 둘 다 없으면 **코드명** → `법정휴일`

후보가 2개 이상인 코드는 `코드 표기(역매핑)` 탭에서 **정리 필요**로 표시된다.

## 9-3. 권한 — 구조는 관리자, 옵션은 현장

| 역할 | 권한 | 할 수 있는 것 |
| --- | :-: | --- |
| 시스템관리자 | ◎ | 양식 등록·편집·버전 관리, 변경 요청 처리 |
| J/C | ○ | 조회 + 변경 요청 |
| 현장관리자 | **▲** | **양식 선택 + 표시 옵션 + 변경 요청** (구조 편집 불가) |
| 근로자 | − | 권한 없음 |

**현장에 열어주는 표시 옵션** (합계·비식별에 영향 없음): 정렬(사번/성명/직군) · 포함 인원(재직자만/퇴사자 포함) · 대상 기간 · 파일명 접미사

**요청 워크플로**: 현장관리자 `원하는 양식이 없음 — 변경 요청` → 시스템관리자 요청 큐 → 합계 대조·비식별 검증 후 반영/반려

## 9-5. 고정 규칙 3가지 (양식으로 끌 수 없음)

1. **합계 대조 행 자동 부착** — 어떤 양식이든 하단에 `합계` / `확정 근태 대조` 2행이 붙어, 총 공수가 확정 근태 합계와 일치하는지 파일 안에서 확인된다 (F-I0106)
2. **고객사 제출 용도는 비식별 강제** — 용도를 `고객사 제출`로 지정하면 비식별이 ON으로 잠기고 편집 화면에서도 변경 불가 (F-J0106 우선)
3. **ERP 전송과 완전 분리** — 조회·제출용 산출물 전용. ERP는 DB 직접 전송이므로 현장 양식이 ERP에 영향을 주지 않는다

# 10. 절대 규칙 (전 화면 적용 · 위반 금지)

1. **원본 불변** — RAW 데이터는 어떤 권한·화면에서도 수정·삭제 불가. 화면은 항상 `원본값 / 확정값`을 구분 표시한다.
2. **4단 이력 구조** — 원본 → 정정 요청 → 관리자 승인값 → 최종 확정값. 각 단계 주체·일시·사유 필수.
3. **임의 추정 금지** — 미수집·미매핑·미등록은 `기록 없음` / `계획 없음` / `변환 실패`로 **명시 표기**. 값을 추정해 채우지 않는다.
4. **AI 결과 확정 금지** — OCR 인식 결과는 `검토 대기`로만 적재. 사람 확인 후에만 반영.
5. **기준값 하드코딩 금지** — 가산율 · 주52시간 · 연장 한도 · 경고 임계치 · 허용오차 · 현장 반경 전부 설정값.
6. **마감 잠금 시 쓰기 전면 차단** — 수집·보정·신청 차단. 조회 · 집계 · ERP 전송만 허용.
7. **채널 충돌 자동 덮어쓰기 금지** — 제모스 값과 다른 채널 값이 충돌하면 양쪽을 나란히 보여주고 **관리자가 선택**. 결과는 Audit Log에 기록되고 원본은 양쪽 모두 보존.
8. **내보내기 양식이 우회할 수 없는 3가지** — 합계 대조 행 부착 · 고객사 제출 용도의 비식별 강제 · 마스킹 정책 우선.
9. **조회도 기록** — Audit Log 조회 · 개인정보 조회 · 산출물 다운로드 모두 이력 기록 (F-J0105).

# 11. 확정된 결정 사항

논의를 거쳐 확정된 항목이다. **"왜 이렇게 됐는지"** 를 남겨둔다.

## ① 근로자 서명 기능 — 미도입

**결정** — 근태 확정에 대한 근로자 서명 절차를 만들지 않는다. 근로자의 역할은 **조회 + 정정 요청**까지다.

**영향** — 1차 확정(F-G0204)과 월 마감(F-H0101)의 차단 조건에서 서명을 **제외**했다.

**대체 통제** — 서명이 없으므로 다음 3가지가 노무 리스크 대응 근거가 된다.
1. 근로자 조회 이력 (Audit Log)
2. 정정 요청 이력 (요청·사유·증빙·승인/반려)
3. 4단 이력 구조

> 기존 미결 M-01("서명 기능 추가 vs 차단 조건에서 제외")은 이 결정으로 종결.

## ② 확정 · 승인 · 마감 단위 — 현장 × 월

**결정** — 1차 확정 · 2차 승인 · 반송 · 마감 · ERP 전송은 모두 **현장 단위**다. 근로자 개별 승인은 하지 않는다.

**이유** — 실제 업무가 현장 단위로 돌아간다. 근로자 9명의 확정 상태를 따로 관리하면 "1차 확정 4/9명" 같은 중간 상태가 생기고, 그 상태로는 J/C가 무엇을 승인해야 할지 판단할 수 없다.

## ③ ERP 연동 — 파일 생성 폐기, DB 직접 전송

**결정** — 엑셀 산출물 생성 + 담당자 수동 업로드 + 업로드 결과 기록(F-I0109) 방식을 폐기하고, **ERP 근태 테이블에 직접 INSERT**한다.

**이유** — 파일 방식은 ① 양식 관리 부담 ② 사람의 업로드 단계 ③ 업로드 결과를 따로 기록해야 하는 부담 ④ 반려 시 역추적 어려움이 있었다. DB 직접 전송은 이 4가지를 모두 제거한다.

**전제** — ERP 근태 테이블 쓰기 권한과 스펙 확보 (§12 ★)

## ④ 근로자 조회 기간 — 확정 대상월 1개월

**결정** — 근로자는 근태 확정 대상월 한 달만 조회한다. 전월 이전은 조회 불가.

**참고** — 현재 프로토타입은 이를 `근태 확정 대상월(2026-08)`로 고정했다. "진행 중인 당월"로 해석해야 한다면 설정값 1곳만 변경하면 된다.

## ⑤ 내보내기 양식 — 데이터로 관리, 구조는 관리자

**결정** — 현장별 제출 서식을 양식 정의 레코드로 관리한다. 구조 편집은 시스템관리자, 현장관리자는 선택 + 표시 옵션 + 변경 요청.

**이유** — 양식은 고객사 제출물의 형식이기도 해서 임의 변경이 대외 영향을 준다. 또한 합계 대조와 마스킹 정책을 양식이 우회하면 안 되므로 활성화 전 검증이 필요하고, 그건 관리자 절차다.

**확산 단계 유보** — 현장이 수십~수백 개로 늘면 관리자가 병목이 된다. 그때는 ① 템플릿 + 제한 커스터마이즈 또는 ② 현장관리자 편집 + J/C 승인 워크플로로 전환한다. 파일럿 3개 현장에서는 병목이 아니다.

4. **확산** — 이식 완료 후 현장별 초기 세팅을 거쳐 그룹 내 전 사업장 도입

**이식 대상 화면** — 근로자 내 근태 확인 · 정정 요청 · 연장근로 신청 (+ 내 대시보드·근무일정 검토)
**PC 웹에 남는 화면** — 현장관리자 · J/C · 시스템관리자 전 화면
