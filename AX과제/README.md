## 착수 계획

- **Wave 1 (2주 내)** — UC-03·04. 보유 Skill(`delay-order-extractor`, `opl-generator`) 재사용, 신규 개발 없음. Quick Win으로 사내 신뢰 확보.
- **Wave 2 (1~2개월)** — UC-01·02. 실질 임팩트의 핵심. 선행 조건은 ① 원장 양식 표준화 ② LOSS 귀책 카테고리 정의서 문서화.
- **Wave 3** — UC-05·06·07·08. 조·반장 입력 채널 표준화, UC-01·02 산출물 확보 후.
- **Wave 4** — UC-09. UC-02 운영 안정화 + 12개월 데이터 정합성 확보 후.

## 설계 원칙 적용 (교재 3장)

1. **선정 기준** — 반복성 · 규칙성 · 검증 가능성 3가지를 동시에 만족하는 업무만 채택. 노무 징계 판단, 협상 전략 수립, 인사 평가는 의도적으로 제외했다.
2. **안전장치** — 전 파이프라인에 검증 단계와 정지 조건을 명시했다. 권한은 읽기 + 신규 파일 생성으로 제한하고, 원본 수정·삭제·외부 전송은 자동 실행 대상에서 제외한다.
3. **되돌리기 경로** — 산출물은 항상 신규 파일·신규 버전으로만 저장한다.
4. **Hook** — 개인정보·원청 자료의 외부 전송 차단처럼 '반드시'가 필요한 항목은 CLAUDE.md 지침이 아니라 Hook으로 건다. 지침은 놓칠 수 있고, Hook은 예외가 없다.

## 리스크

- **노무** — 개인 근태·점검 지적을 개인 단위로 리포팅하면 도급 인력에 대한 직접 지휘 소지가 생긴다. 전 산출물은 공정·항목 단위로만 집계한다.
- **정보보안** — 원청 자료(생산계획·물량·점검 통지문)와 개인정보는 사내 처리 한정.
- **자산 통제** — LOSS 귀책 분류 로직과 카테고리 정의서는 협상 결정 자산이다. 산출물에는 결과 수치만 담고 로직은 포함하지 않는다.
