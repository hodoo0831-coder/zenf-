# MES LOSS 귀책 분류 파이프라인 (UC-02)

대상 월: **$1**

## 목적
LOSS 사유를 매번 같은 기준으로 원청/도급/공통 분류한다. 분류공수 16H → 3H, 동일 사유코드 이중 분류 0건.

## 처리 절차

### 1. 입력 확인
추출 행 수가 전월 대비 ±50% 이상 차이 나면 추출 오류를 의심해 확인을 요청한다.

### 2. 사유코드 분포 요약 (정지 지점)
사유코드 분포를 먼저 보여준다. **카테고리 정의서에 없는 신규 사유코드가 있으면 분류하지 말고 질문**한다.

### 3. 분류 (분류 서브에이전트)
사유 텍스트를 정규화한 뒤 귀책 분류 룰을 적용한다.
- 룰에 매칭되지 않는 건은 **추측 분류 금지**, `보류`로 격리한다.
- 공통 LOSS를 50:50으로 임의 배분하지 않는다. 발생 사유별로 귀책을 판정한다.
  (자재 미입고 = 원청 / 휴식 미복귀 = 도급 / 설비 워밍업 = 공통)

### 4. 두 축 산출 (합산 금지)
- **LOSS 비용** = 비조업 공수 × 임률 — 정산·협상 근거
- **효율 GAP 환산** = 월 공수 × (목표효율 − 실효율) / 100 × 임률 — KPI 미달 비용(추정치)

두 값이 다른 것이 정상이다. 하나로 합치지 않는다.

### 5. 검증 (정지 지점)
1. 귀책별 합계 공수 = 원본 총 공수 일치
2. 표본 50행 역검증 — 같은 사유코드가 다른 귀책으로 분류된 건 0
3. 보류 비율 10% 이하

보류 10% 초과 또는 이중 분류 1건이라도 발견되면 **저장 중단 후 보고**한다.
(같은 문제가 3회 반복되면 결과를 고치지 말고 분류 룰 구조부터 재검토한다.)

### 6. 저장
월간 LOSS 리포트를 신규 파일로 저장하고, 보류건은 사람 판정 목록으로 별도 생성한다.

## 제약
- 분류 룰은 자동 변경 금지. 룰 수정은 사람만 한다.
- 원청 제출본은 센터장 승인 전에 생성하지 않는다.
- 분류 로직·카테고리 정의서 내용은 어떤 산출물에도 포함하지 않는다(내부 자산). 결과 수치만 담는다.
