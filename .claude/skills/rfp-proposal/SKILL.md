# RFP 분석 · 제안서 초안 Skill

## 1단계 — 추출 (표로 정리)
| 구분 | 내용 |
|---|---|
| 요구사항 목록 | R-01, R-02 … 번호를 부여해 전수 나열 |
| 평가 기준과 배점 | 항목 / 배점 / 평가 방식 |
| 제출 마감일 | |
| 제출 형식 | 매수·파일형식·필수 서식 |

**원문에 없는 항목은 추측하지 말고 `RFP 미기재` 로 표기한다.**

## 2단계 — 표준 목차로 초안 작성
1. 제안 개요
2. 제안 배경·목적
3. 요구사항별 제안 내용 ← 요구사항 번호(R-01…)를 각 절에 명시
4. 수행 일정
5. 수행 조직
6. 기대 효과

자사 정보가 필요한 부분은 **`[회사 정보 입력]`** 으로 표시한다. 지어내지 않는다.

## 3단계 — 검증 (생략 불가)
요구사항 목록과 초안을 **1:1 대조**한다.

| 요구사항 | 반영 위치 | 반영 상태 | 비고 |
|---|---|---|---|
| R-01 | 3.1절 | 반영 / 불충분 / **누락** | |

추가 검증 항목:
- **평가 기준별 대응 내용이 초안에 포함되어 있는가** (배점 높은 항목 우선 확인)
- 제출 형식(매수·서식) 요건을 초안이 충족하는가

**누락·불충분이 1건이라도 있으면 완료 처리하지 말고 표로 보고한다.**

## 4단계 — 저장
`YYYYMMDD_[사업명]_제안서초안_v1.docx` 로 **신규 파일**만 생성. 기존 파일 덮어쓰기 금지.

## 금지
- 외부 자동 발송·전송 (어떤 경우에도 포함하지 않는다)
- RFP에 없는 내용 창작
