## 화면 골격

```html
<div id="app">
  <header class="topbar">
    <button class="tb-menu">☰</button>              <!-- 1024 미만에서만 보임 -->
    <div class="tb-logo"><b>젠타임</b><small>ZENTIME</small></div>
    <span class="tb-sp"></span>
    <select class="tb-sel">…</select>               <!-- 대상월 등 전역 선택 -->
    <div class="tb-av">김</div>
    <div class="tb-who"><b>김태윤</b><small>현장관리자</small></div>
    <button class="tb-out">로그아웃</button>        <!-- 1024 이상에서만 -->
  </header>
  <div class="ctxbar">…</div>                       <!-- 지금 보고 있는 범위 -->
  <div class="shell">
    <nav class="side">…</nav>                       <!-- 1024 이상 -->
    <main class="main" id="main">…</main>
  </div>
  <nav id="tabbar">…</nav>                          <!-- 1024 미만 -->
  <div id="drawer">…</div>                          <!-- 모바일 전체 메뉴 -->
</div>
```

**같은 메뉴를 세 벌 만들지 말고 하나의 데이터에서 세 곳을 그린다.** 좌측 `.side`(PC),
하단 `#tabbar`(모바일 주요 4~5개), 드로어 `#drawer .pane`(모바일 전체)이 같은 메뉴
배열을 읽게 하면 화면이 늘어도 어긋나지 않는다.

**컨텍스트 바**는 "지금 무엇을 보고 있는지"를 항상 띄워두는 줄이다 — 대상월, 현장 범위,
마감 상태, 데모/라이브 여부. 관리 화면에서 사용자가 가장 자주 헷갈리는 것이 "이 숫자가
어느 달 어느 현장 것이냐"이므로 화면마다 반복해 쓰지 말고 여기 한 줄로 고정한다.
sticky이며 `top`은 상단바 높이에 맞춘다.

**사이드바 활성 표시**는 배경을 칠하지 말고 왼쪽에 2px 네이비 막대를 세우고 글자를
네이비 700으로 바꾼다. 배경 블록은 헤어라인 톤을 깨뜨린다.

```css
.navi.on{color:var(--navy);font-weight:700;background:transparent}
.navi.on::before{content:"";position:absolute;left:-14px;top:10px;bottom:10px;
  width:2px;background:var(--navy)}
```

## 페이지 헤더

```html
<div class="ph">
  <div class="k">현장관리자 · SCR-M-03</div>
  <h1>월 근태 등록 · 확정</h1>
  <p>1인 1행 × 31일 그리드입니다. 셀을 누르면 상세와 <b>제모스 원본값</b>이 열립니다.</p>
  <div class="fids"><span class="fid">F-D0105</span><span class="fid">F-D0106</span></div>
</div>
```

`.k`는 역할·화면번호 같은 좌표, `p`는 **이 화면이 무엇을 대신해 주는지** 한두 문장.
기능 나열이 아니라 "손으로 하던 무엇이 없어지는가"를 쓴다. `.fid` 칩은 기능정의서
항목번호를 달아 문서와 화면을 이어주는 용도다 — 그런 문서가 없는 앱이면 생략한다.

머리가 길어지면 정작 일하는 표가 접힌다. 설명은 2줄을 넘기지 않는다.

## 카드

```html
<section class="card">
  <div class="card-h">
    <span class="card-t">현장별 마감</span>
    <span class="card-s">26년 8월 · 현장 단위</span>
    <span class="sp"></span>
    <button class="btn sm">전체 보기</button>
  </div>
  <div class="card-b">…</div>
</section>
```

표나 그리드를 넣을 때는 `card-b` 대신 `card-b np`(no padding)를 쓰고, 표 첫·끝 칸에
`--pad`를 줘서 제목선에 맞춘다(base.css에 규칙이 들어 있다).

`.foot`은 카드 맨 아래 주석 — 규칙·주의사항을 적는다. 회색 작은 글씨지만 현장에서는
이 줄을 제일 많이 읽는다("제모스 원본값은 절대 덮어쓰지 않습니다" 같은 것).

## 통계 타일

```html
<div class="tiles">
  <div class="tile"><div class="tl">현장 인원</div>
    <div class="tv">9<u>명</u></div><div class="td">제모스 사용률 100%</div></div>
  <div class="tile acc-e"><div class="tl">확인 필요</div>
    <div class="tv">54<u>건</u></div><div class="td">마감 차단 20건 포함</div></div>
</div>
```

칸 사이에 여백을 두지 않고 1px 선으로만 나눈다(`gap:0` + border). 그래야 카드 무더기가
아니라 한 장의 표처럼 보인다. 단위는 `<u>`로 감싸 작게 — 숫자가 주인공이다.

`.td` 보조설명에 **"그래서 뭘 해야 하는지"**를 적는다. "54건"만으로는 행동이 안 나온다.
`acc-e`(빨강) / `acc-w`(주황)는 조치가 필요한 수치에만.

수치는 `font-variant-numeric:tabular-nums`로 자릿수가 흔들리지 않게 한다(base.css에서
body에 걸어둠).

## 표 · 리스트 카드

**PC는 표, 모바일은 리스트 카드.** 열이 5개를 넘는 표를 320px에서 가로 스크롤로 밀면
아무도 안 본다. 같은 데이터를 두 벌로 그리고 `@media`로 하나만 띄운다.

`.only-pc` / `.only-mb`가 768px에서 갈라준다.

```html
<div class="only-pc tw"><table class="tb">…</table></div>
<div class="only-mb lc">
  <div class="lch"><span class="lct">서지수</span><span class="tag t-err">퇴근 태그 누락</span></div>
  <div class="lcd">8/5 · 제모스 출퇴근 · 07:57 ~ 없음</div>
  <div class="lcb"><button class="btn sm pr">보정</button></div>
</div>
```

예외는 **날짜축 그리드**처럼 표 모양을 유지해야만 뜻이 통하는 것 — 이건 리스트 카드로
바꾸지 말고 `.tw` 안에서 가로 스크롤시키고 `.tw-hint`("옆으로 밀어서 보세요")를 붙인다.

표 머리글은 `--faint` 700에 자간을 벌리고, 아래에 **네이비 1px 선**을 긋는다. 행 구분선은
`--line2`로 더 흐리게 — 머리글 선만 진해야 표가 안 흐트러진다.

행 여백은 데스크톱에서 9px까지 줄여도 된다. 행 안의 버튼은 40px를 지킨다.

## 진행 단계 · 체크리스트

`.steps`는 **여러 사람을 거치는 절차**를 보여줄 때 쓴다(수신 → 예외처리 → 1차확정 →
2차승인 → 마감). 지금 어디고 다음이 누구 차례인지가 한눈에 보여야 한다.
모바일에서는 세로, 720px 이상에서 가로로 눕는다.

```html
<div class="steps">
  <div class="step done"><span class="sn">✓</span>
    <div><span class="st">제모스 수신 · 자동검증</span><span class="sd">일 배치로 태그를 받아 V-01~15 검증</span></div></div>
  <div class="step now"><span class="sn">2</span>
    <div><span class="st">예외 처리 (현장)</span><span class="sd">확인 필요 54건</span></div></div>
</div>
```

활성 단계는 `.step.now`, 지난 단계는 `.step.done`이다(`.on`이 아니다 — 사이드바·탭바만
`.on`을 쓴다).

`.sn`과 본문은 `.step{display:flex}`의 형제이므로 **제목·설명은 `<div>`로 한 번
감싼다.** 안 감싸면 `.st`/`.sd`가 각각 flex 아이템이 되어 한 줄에 나란히 붙는다.

`.ck`는 이름이 체크리스트지만 **읽는 것**이다 — 규칙·정책을 번호와 함께 늘어놓는 자리이지
사용자가 눌러서 판정하는 위젯이 아니다. 점검 앱처럼 **탭해서 OK/NG를 매기는 행**이
필요하면 그건 앱마다 만든다(행 하나에 항목명 + 40px 버튼 3개면 충분하고, `.lc` 리스트
카드를 변형하는 게 가장 빠르다).

## 배지 · 태그 · 노트

`.tag`는 상태 한 단어. 색은 의미로만 고른다 —
`t-ok`(정상·완료) · `t-warn`(주의·대기) · `t-err`(오류·차단) · `t-info`(참고) ·
`t-gr`(초록 — 정상 판정) · `t-gy`(회색 — 해당없음·비활성) · `t-pp`(자주 — 의미 없는 구분용).

`.note`는 화면 위쪽의 안내 블록. 규칙이나 판정 기준처럼 **틀리면 손해 보는 정보**를 담는다.
장식으로 쓰면 사용자가 곧 무시하게 되므로 화면당 한 개를 넘기지 않는다.

## 버튼 · 탭

```html
<button class="btn pr">1차 확정</button>     <!-- 주동작: 네이비 채움 -->
<button class="btn nv">상세 보기</button>    <!-- 부동작: 네이비 테두리 -->
<button class="btn">취소</button>            <!-- 중립: 회색 테두리 -->
<button class="btn sm">보정</button>         <!-- 표 안 · 40px 유지 -->
<button class="btn dg">반려</button>         <!-- 파괴적 -->
```

**화면당 주버튼은 하나.** 두 개가 나란히 네이비면 어느 쪽이 다음 행동인지 알 수 없다.

탭 활성은 밑줄 2px 네이비. 상자로 감싸지 않는다.

## 모달 · 토스트

모달은 `max-width:660px`, `max-height:92vh`, 본문만 스크롤. 모바일에서는 아래에서 올라오는
시트처럼 붙인다. 제목 `.mh h3`는 17.5px 700.

토스트는 화면 하단 가운데, 3초. **되돌릴 수 없는 동작을 알릴 때만** 쓰고, 저장 같은 흔한
동작은 화면 상태로 보여준다.

## 데이터 그리드 · 캘린더

`table.mgt`는 1인 1행 × 날짜 열 그리드다. 사람 이름 열은 `position:sticky; left:0`으로
고정하고 오른쪽에 1px 선을 준다. 셀은 40px(1024 이상에서 34px)이고 상태를 옅은 배경색으로
칠하되, **손댈 필요가 있는 셀만 테두리로 표시**한다 — 정상 셀까지 강조하면 아무것도 안 보인다.

`.cal`은 근로자 본인용 월 달력. 관리자는 그리드, 근로자는 달력 — 보는 단위가 다르다.

색만으로 상태를 구분하지 말고 범례(`.mg-lg`)를 붙이고 글자·기호를 함께 쓴다.

## 로그인

`.lg`는 880px 이상에서 `1fr 380px` 2단이 된다. 왼쪽에 이 시스템이 **무엇을 하고 무엇을
하지 않는지**, 오른쪽에 로그인 카드.

"하지 않는 것"을 적는 칸이 의외로 중요하다. 사내 시스템은 도입 초기에 "이걸로 출퇴근도
찍나요?" 같은 오해가 반드시 생긴다. 경계를 먼저 못박으면 문의가 줄어든다.

SSO 연동 전이라면 역할별 데모 계정을 눌러서 자동 입력되게 한다(`.acct`). 시연에서
아이디를 타이핑하는 시간이 사라진다.

## 앱마다 다시 판단할 것

base.css에는 근태 앱에서 나온 것들이 섞여 있다. 다른 앱을 만들 때는 그대로 쓰지 말고
바꾼다:

- **컨텍스트 바의 내용** — 근태는 "대상월 · 현장 · 마감상태"였다. 생산이면 "라인 · 일자 ·
  교대", 점검이면 "현장 · 점검일 · 차수"가 될 것이다. 줄 자체는 유지하되 항목은 바꾼다.
- **`table.mgt` 근태 그리드 · `.cal` 달력** — 날짜 축이 있는 앱에만 해당한다.
- **`.fid` 기능정의서 칩** — 그런 문서가 있는 프로젝트에서만.
- **역할 구분** — 근태는 근로자/현장관리자/J·C/시스템관리자 4역할이었다. 역할 수가 다르면
  아바타 네이비 농담 단계도 그에 맞춰 다시 나눈다.
